# Подробное описание проекта: Автоматизация PHPTravels

Этот проект — семестровая работа по автоматизированному тестированию веб-приложения `https://phptravels.net`. Проект построен на языке Java с использованием Selenium WebDriver и JUnit 5.

## 🎯 Соответствие требованиям (pozadavky.txt)
Проект полностью покрывает требования для получения максимального балла:
*   **Selenium:** Реализовано 10+ тестов (Flights, Visa, Login).
*   **Data-Driven Testing (DDT):** Минимум 3 сценария используют данные из CSV-файлов (`flights_data.csv`, `login_data.csv`, `visa_data.csv`).
*   **Архитектура:** Использован паттерн **Page Object Pattern (POP)**.
*   **Сложные сценарии:** Тесты покрывают не только позитивные пути, но и негативные (одинаковые города, неверные пароли, пустые даты).

---

## 🛠 Технологии и Библиотеки
Мы используем следующие инструменты (прописаны в `pom.xml`):
1.  **Java 17:** Основной язык программирования.
2.  **Selenium Java (4.20.0):** Библиотека для управления браузером (клики, ввод текста, поиск элементов).
3.  **JUnit 5 (Jupiter):** Фреймворк для запуска тестов и проверки результатов (Assertions).
    *   `junit-jupiter-api` — для написания тестов.
    *   `junit-jupiter-params` — для параметризованных тестов (чтение из CSV).
4.  **Maven:** Менеджер проекта. Он сам скачивает все вышеуказанные библиотеки, тебе не нужно ничего устанавливать вручную.

---

## 🏗 Структура проекта
*   **`src/main/java/.../pages/`**: Тут лежат "Страницы" (Page Objects). В них описаны элементы сайта (кнопки, поля) и действия с ними. Это сделано для того, чтобы если на сайте изменится кнопка, нам нужно было поправить её только в одном месте, а не во всех тестах.
    *   `BasePage`: Общие методы (ожидания, клики с проверкой).
*   **`src/test/java/.../tests/`**: Сами тесты. Они вызывают методы страниц и проверяют результат через `assertTrue` или `assertFalse`.
    *   `BaseTest`: Настройка браузера (Chrome), его запуск и закрытие, а также автоматическое создание скриншотов при падениях.
*   **`src/test/resources/`**: CSV-файлы с тестовыми данными.

## 💡 Полезные советы и настройки

### 1. Как изменить скорость тестов?
Если тесты летят слишком быстро и ты не успеваешь увидеть, что происходит, или наоборот — хочешь ускорить:
*   В классах страниц (например, `FlightsPage.java`) я добавил метод `sleep(ms)`.
*   Найди вызовы `sleep(1000)` (это 1 секунда) и увеличь их до `sleep(3000)`, если хочешь замедлить.
*   **ВАЖНО:** В реальной работе `Thread.sleep` — это плохо, лучше использовать `WebDriverWait` (который у нас тоже есть в `BasePage`), но для защиты проекта паузы помогают показать преподавателю, что тест реально кликает.

### 2. Как запустить тесты без открытия браузера (Headless)?
Если нужно запустить тесты в фоне (например, на сервере):
*   Зайди в `BaseTest.java`.
*   Раскомментируй строку: `// options.addArguments("--headless");`.

### 3. Где смотреть ошибки?
*   Если тест упал, в папке `target/screenshots` появится скриншот экрана в момент ошибки.
*   В консоли IntelliJ IDEA (вкладка Run) будет написано "Expected: true, Actual: false" и ссылка на строку в коде, где произошел сбой.

## 🧪 Описание всех тестовых сценариев

В проекте реализовано 10+ тестов, разделенных по функциональным модулям.

### 1. Модуль Авторизации (LoginTest)
*   **`testLoginRedirect`**: Проверяет, что при переходе по ссылке `/login` открывается именно страница логина.
*   **`testInvalidLoginMessage`**: Негативный тест. Вводит неправильную почту и пароль, после чего проверяет, что на экране появилось сообщение об ошибке (содержащее слова "Invalid", "Wrong" или "failed").
*   **`testLoginNegativeData` (DDT)**: Параметризованный тест, который берет разные пары неверных данных из `login_data.csv`. Проверяет, что система НЕ пустила пользователя в личный кабинет (URL не содержит `/account`).

### 2. Модуль Перелетов (FlightsTest)
*   **`testSuccessfulFlightSearch`**: Базовый позитивный сценарий. Выбирает Дубай -> Лондон, устанавливает дату и нажимает поиск. Проверяет, что URL изменился на страницу результатов.
*   **`testFlightSearchData` (DDT)**: Прогоняет поиск для разных городов и дат из `flights_data.csv`. Гарантирует, что поиск работает для разных направлений.
*   **`testFlightSearchSameCity`**: Негативный тест. Пытается найти билет из Дубая в Дубай. Проверяет, что система не переходит к результатам (так как лететь в тот же город нельзя).
*   **`testValidFutureDate`**: Проверяет поиск на конкретную дату в будущем (текущая дата + 14 дней). Это важно, так как сайт часто блокирует прошлые даты.

### 3. Модуль Виз (VisaTest)
*   **`testVisaCheck` (DDT)**: Использует данные из `visa_data.csv` (Чехия -> Египет и др.). Проверяет, что после ввода данных мы попадаем на страницу с требованиями визы или формой подачи.
*   **`testVisaSubmissionProcess`**: Проверяет полный путь: выбор стран (Украина -> Египет), установка даты и переход к деталям визы для этой страны.
*   **`testVisaSameCountryError`**: Негативный тест. Проверяет, что при выборе одинаковых стран (Украина -> Украина) появляется сообщение о том, что страны должны быть разными.
*   **`testVisaEmptyDateError`**: Проверяет обработку пустых полей. Очищает дату и нажимает поиск, ожидая сообщение об ошибке "Date is required".

## 🚀 Как запустить проект первый раз?
1. Открой `pom.xml`.
2. Дождись завершения "Indexing" и "Downloading dependencies" внизу экрана.
3. Открой любой файл из папки `tests`.
4. Нажми на зеленый треугольник слева от названия класса.
